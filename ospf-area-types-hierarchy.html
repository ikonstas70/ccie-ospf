OSPF Area Types & Hierarchy

Stub areas, Totally Stubby areas, and NSSA all exist to answer one question: how much of the outside world does this area actually need to see? The rule that decides it isn't topology — it's configuration, plus one hard constraint on ASBRs.

Core Router Roles

Internal router — every interface belongs to the same area.

ABR (Area Border Router) — sits on the boundary between two or more areas and exchanges routing information between them.

Area 0 <----> ABR <----> Area 1

ASBR (Autonomous System Boundary Router) — redistributes routes from another source (static, BGP, EIGRP, RIP) into OSPF, generating external routes.

Normal (Non-Stub) Area

Accepts every LSA type that's valid for OSPF — intra-area (Type 1/2), inter-area (Type 3/4), and external (Type 5). Nothing is filtered. Think: "give me everything."

         ASBR
           |
         Area 0
           |
         Area 1
Stub Area

A stub area blocks Type 5 external LSAs and has the ABR inject a single default route (0.0.0.0/0) instead. Type 1, 2, and 3 LSAs still get through.

Configured on every router inside the area 
router ospf 1
 area 1 stub

Instead of carrying thousands of individual external routes, routers inside the area carry one: 0.0.0.0/0, pointed at the ABR. Smaller LSDB, smaller routing table, less SPF work. Think: "don't send me external routes."

Totally Stubby Area (Cisco)

A Cisco-proprietary tightening of Stub: it also blocks Type 3 inter-area LSAs, keeping only the default route for anything outside the area.

ABR 
area 1 stub no-summary
Internal routers 
area 1 stub

Allowed: Type 1, 2, plus the injected default. Blocked: Type 3, 4, 5 (except the default route itself). This produces the smallest possible routing table. Think: "just give me a default route."

Can a Stub Area Contain an ASBR?

No — and this is the single most important rule in this topic. An ASBR generates external routes, which become Type 5 LSAs. Stub areas exist specifically to block Type 5 LSAs. The two requirements directly conflict, so Cisco simply does not allow an ASBR inside a configured stub area.

NSSA — Not-So-Stubby Area

NSSA exists for exactly the case Stub can't handle: you want stub-like behavior, but the area still needs to redistribute routes locally through its own ASBR.

Area 0
   |
  ABR
   |
 NSSA
   |
 ASBR
Configuration 
router ospf 1
 area 1 nssa

Inside the NSSA, the ASBR's redistributed routes are carried as Type 7 LSAs rather than Type 5. The ABR translates Type 7 → Type 5 only when advertising them onward into the rest of the OSPF domain. Allowed inside the NSSA: Type 1, 2, 3, 7. Blocked: incoming Type 5 from outside. Think: "mostly stub, but I still need redistribution."

A Cisco enhancement, Totally NSSA, combines this with the Totally Stubby restriction: it can still originate Type 7 externals locally, but receives only a default route for everything outside, with Type 3/4/5 blocked.

The Common Misconception

A tempting shortcut is: "any area that isn't Area 0, has no ASBR, and only connects out through an ABR, is automatically a stub area." That's not correct — a stub area is defined by configuration and LSA filtering, not by topology alone.

Area 0 ---- ABR ---- Area 1

If Area 1 has no ASBR but was never configured with area 1 stub, it is simply a normal area that happens to have no external routes to advertise. Nothing about its shape forces stub behavior — the command has to be there.

Corrected rule: a stub area is an area explicitly configured as stub, that does not contain an ASBR. Topology without configuration is never enough on its own.

One related detail worth flagging precisely: the OSPF network-type command (ip ospf network point-to-point) is a different, interface-level setting and isn't removed by IOS just because a neighbor also configures it — it stays in the running config on both sides, since it's a valid explicit setting rather than a derived default.

Memory Trick
  • Normal = everything
  • Stub = no external routes
  • Totally Stubby = only a default route
  • NSSA = stub with a local ASBR (Type 7 → Type 5 at the ABR)

Golden rule: a stub area is never determined by topology alone. It must be explicitly configured as stub, and it can never contain an ASBR — that constraint is the fastest way to rule stub/totally-stubby in or out of any diagram.
